# AI_LOG

## Tools used

- **Claude Code** (model: Claude Opus 5.5) as a pair programmer in the terminal: planning, writing
  code, running lint/typecheck/tests/build, secret scans, deploys and git commands. I reviewed every
  change (staged diff and secret scan) before it was committed.
- **Reading official documentation** through the assistant: Google's Gemini docs (model names,
  free tier, structured-output request format, thinking levels) instead of relying on memory.
- **A throwaway browser script** (headless Microsoft Edge driven over the DevTools protocol with
  Node's built-in WebSocket, not committed) for end-to-end tests on the live demo (upload the sample
  PDF, wait for results, check the page has no horizontal overflow at 360 px) and for the README
  screenshot.

## Key prompts

1. **Project brief and working rules** — I pasted the full recruitment brief (features F-01..F-10,
   schema, stack, security rules) plus my own working rules: secrets first, secret scan before every
   commit, small Conventional Commits, phases with lint/tsc/test/build after each, "interview notes"
   after each phase, wait for my "go" before committing.
2. **Commit discipline** — "Before I say go: confirm the secret scan passed on the staged files and
   show me git diff --staged for the commit." (This caught a BOM added to `package.json`.)
3. **CORS and limits review (Phase 4)** — "The origin allowlist must be exactly
   https://webmasterfed.github.io (scheme and host only, no path and no wildcard), with localhost
   only through an env variable. Note in the README that the in-memory rate limiter resets when the
   function instance restarts and isn't shared between instances."
4. **Result quality review after testing the sample PDF** — "Scan detection: count the letters and
   digits on each page… show a clear Polish warning… pass this information to the API and include a
   short note in the model prompt that some pages could not be read. Tighter amounts: … only the
   amounts that define the document, with at most 20 entries. Accurate wording: copy names, titles
   and context wording exactly as in the document." (Page 11 of the sample is a scanned annex; the
   output had ~55 amounts and the typo "koszutu".)
5. **Shared rate limiter (Phase 8)** — "A: build the shared limiter in Postgres. Before I run any
   SQL, show me the full SQL block and explain each part in plain language (the table, the atomic
   function, RLS enabled with no policies, and that only service_role can execute it). The
   service-role key must stay only in the function's injected environment, never in git, the
   frontend or logs, and the secret scanner must keep checking for it." (After a live test showed the
   in-memory limiter never triggered.)

## Other problems during the project (not AI mistakes)

- **Phase 1, first push:** `Repository not found`, then `403 Permission denied` for a different
  GitHub account. The repo was private and Git Credential Manager used a saved login for that other
  account. Diagnosed with the public GitHub API (404 meant private), made the repo public (needed
  for Pages on a free plan) and set the remote to
  `https://webmasterfed@github.com/webmasterfed/pdf-insight.git` so the credential manager picks the
  correct account.
- **Phase 8, secret scanner:** the brief's suggested `service_role` pattern matched the role name
  itself, which appears legitimately in SQL grants and in the env variable name
  `SUPABASE_SERVICE_ROLE_KEY`. Changed it to match key values (JWT, `sb_secret_…`, an assigned
  `SERVICE_ROLE_KEY=<value>`); tested with 5 fake secrets (blocked) and 3 harmless mentions
  (allowed).
- **Phase 6, screenshots:** the AI's first "light theme" screenshots were actually dark, because
  headless Edge follows the Windows dark setting. The browser script now sets the theme explicitly.
  No impact on the product (it also confirmed dark mode follows the OS).
